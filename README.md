# סל חכם 🛒 — השוואת סל אמיתית בין חצי חינם, רמי לוי ושופרסל

תוסף כרום שמקבל רשימת קניות, בונה **עגלה אמיתית בכל אחד משלושת האתרים**, קורא את המחירים **מהאתר עצמו**,
ומראה איפה הסל הכי משתלם, כולל משלוח והנחות אישיות. בסוף יש כפתור "עבור לעגלה" לכל רשת, ונשאר רק לשלם.

> **סטטוס: גרסה 0.1, טרם נבדקה מול האתרים האמיתיים.** האתרים חוסמים גישה משרתי ענן, ולכן הפיתוח והבדיקות
> נעשו מול אתרים מדומים שנבנו לפי תיעוד הממשקים ([docs/SITES.md](docs/SITES.md)). ההרצה הראשונה במחשב שלכם היא
> הבדיקה האמיתית. לתוסף יש דף **אבחון** שמפיק דוח (בלי מידע אישי) לתיקון מהיר של מה שלא יעבוד.

## מה זה עושה

| קלט | פלט |
|---|---|
| התחברות לכל רשת (באתר עצמו, התוסף לא רואה סיסמה) | עגלה מלאה בכל רשת |
| רשימת קניות בטקסט חופשי | סה"כ לכל רשת: מוצרים (מהאתר) + משלוח − הנחות אישיות |
| כתובת, הנחות מועדון/כרטיס אשראי, דמי משלוח ידניים (אופציונלי) | המלצה: הסל המשתלם ביותר, ולמה |
| | השוואה שורה-אחר-שורה: זהה / דומה / שונה / חסר, ומה הזול ביותר |
| | מבצעים ששווה לשקול, מוצרים שהתייקרו, "אולי שכחת" |
| | כפתור **"עבור לעגלה"** לכל רשת |

המוצרים נבחרים לפי היסטוריית הקניות (מה שרגילים לקנות), ואפשר להחליף כל בחירה לפני מילוי העגלות. התוסף זוכר את ההחלפות.

## התקנה ושימוש
ראו **[docs/INSTALL.md](docs/INSTALL.md)**. בקצרה: `chrome://extensions` ← מצב מפתחים ← "טען תוסף לא ארוז" ← התיקייה `extension`.

## אבטחה
ראו **[docs/SECURITY.md](docs/SECURITY.md)**. בקצרה:
- לתוסף יש גישה **רק** לשלושת אתרי הרשתות. הוא עצמו חסום מלשלוח מידע לכל מקום אחר (אין שרת).
- הוא **לא נכנס לדפי תשלום ולא מבצע הזמנה**. אין בקוד פעולה כזאת, וכתובות קופה/תשלום חסומות.
- לא רואה ולא שומר סיסמאות או פרטי אשראי. הנתונים נשמרים רק במחשב שלכם, ויש כפתור מחיקה.

## מגבלות ידועות
- **חצי חינם**: ריקון עגלה, הפחתת כמות והיסטוריית הזמנות עדיין לא נתמכים, כי הממשקים האלה לא מתועדים.
- **רמי לוי**: אין עדיין היסטוריית הזמנות ברמת מוצר.
- דמי משלוח: נקראים מהאתר כשהוא חושף אותם, אחרת מההגדרה הידנית.
- כתובת המשלוח נקבעת באתר של כל רשת. התוסף לא משנה אותה.

## מבנה הריפו

```
extension/            התוסף (MV3, בלי build ובלי תלויות)
  app/                הממשק (עברית, RTL) ו"המנצח" שמריץ את התהליך
  engine/             מנוע ההחלטות: העדפות מהיסטוריה, בחירת מוצר, השוואה והמלצה
  sites/              מתאם לכל רשת + שומר הסף (guard) שחוסם דפי תשלום
  diag/               דף אבחון + השחרת מידע (redaction)
  background.js       ניהול הלשוניות של האתרים
docs/                 SPEC, SITES (ממשקי האתרים ורמת הוודאות), SECURITY, INSTALL
tests/                engine, adapters, app (יחידה) · e2e (התוסף האמיתי בכרומיום מול אתרים מדומים)
.claude/skills/hatzi-hinam-shopper/   הגרסה הראשונה: סקיל ל-Claude לחצי חינם בלבד
```

## בדיקות

```bash
npm test                 # מנוע + מתאמים + תהליך
node --test --test-concurrency=1 tests/e2e/*.spec.mjs   # קצה-לקצה (דורש Playwright + Chromium)
python3 -m unittest discover -s tests                   # מנוע הסקיל המקורי
```

בדיקות הקצה-לקצה מריצות את התוסף האמיתי כשכתובות שלושת האתרים ממופות לשרת מדומה מקומי, ומוודאות בין השאר:
שלוש עגלות מתמלאות והסכומים נקראים מהאתר, אף בקשה לא יוצאת למקור אחר, אין נגיעה בכתובת checkout, והאסימון של
האתר לא נשמר ולא מופיע בדוח האבחון.

## הדגמה (בלי התקנה ובלי התחברות)

`demo/` בונה דף אחד שמריץ את הממשק האמיתי של התוסף מול שלוש רשתות מדומות שחיות בתוך הדף (מוצרים ומחירים מומצאים).
הדף מראה את כל התהליך, מרשימה ועד השוואה והמלצה. הוא לא מתחבר לאתרים האמיתיים ואינו הוכחה שהתוסף עובד מולם.

```bash
npm i --no-save esbuild        # כלי בנייה להדגמה בלבד, התוסף עצמו נשאר בלי תלויות
node demo/build.mjs node_modules/.bin/esbuild      # יוצר demo/dist/sal-hacham-demo.html
```
